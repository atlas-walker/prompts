Diagram summary: 1) The user selects a branch, configuration and test-case IDs in the UI; the selection is sent to the Orchestrator as a JSON payload. 2) The Orchestrator clones or fetch-updates the Bitbucket repository into its Git cache. 3) Feature files are scanned for the requested case IDs and the matching Gherkin scenarios are read into an in-memory model. 4) Feature files are generated in parallel — one per case ID — and staged in the in-memory model together with a configuration.properties pulled from the MongoDB Config DB. 5) The staged bundle travels together to CloudBees. 6) CloudBees hands the build to Atlas, the containerized runtime on GKE (Kubernetes on GCP); a fresh Docker container spins up with only the sent files and runs Gradle via runners.RunConvertTest. 7) From inside the Atlas container, Craft streams execution logs and reports each case's status back to the Orchestrator: QUEUED, EXECUTING, then PASSED or FAILED.
